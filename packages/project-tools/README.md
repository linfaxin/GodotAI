# Project tools

`@godot-js/project-tools` owns the shared, browser-neutral project emitter, native
UID cache handling, module paths, scene-text parser, source maps and PCK writer.
Its neutral entries have no React, Godot runtime, DOM host or filesystem imports.
Node filesystem integration has a separate entry. TypeScript and esbuild are tool
dependencies; bundler execution is injected.

`createSourceSnapshot` → `createBuildPlan` → `prepareBuildPlan` → `packBuildPlan`
keeps source bytes separate from the artifact overlay. Overlay records include
input/output hashes and why a file changed. A plan's `inputs` must include the
actual engine/optional extension identity, tool/options/resolution identities and
resource conversion inputs used by its caller. UI revisions are not content
identity. Pack hashes remain in the outer receipt, avoiding self-referential IDs.

The internal source snapshot is version 2. It owns typed bytes within one build;
`SourceFile.bytes` and public file-map reads return isolated `Uint8Array` copies.
The emitter, overlay and PCK writer reuse private owned bytes, including through
React startup adapters. `snapshotFiles()` and the project-document writer are
explicit JSON boundaries and retain legacy `number[]` serialization. Changing
the in-memory representation does not migrate stored projects or change the
path/encoding/content inputs of `sourceHash`. PCK layout and byte budgets are
checked before file copies and final allocation; directory hashes cover each
view's exact byte range.

Schema 4 has a single engine runtime and an explicit scene or script launch.
`readProjectDocument` adapts schemas 1–3 without writing them. The writer accepts
only explicit schema 4 documents; existing editor storage continues using its
existing schema until migration is deliberately enabled. Legacy React requires
an explicit preparation adapter from `@godot-js/react-build/core`.

Import receipts are created only after successful conversions. Their source and
dependency hashes, parameters, converter version, target resource ABI/features,
and output hashes determine freshness. Scanning legacy imported bytes does not
create proof of a converter run: missing receipts remain `unverified`.

The old `@godot-js/react-build` helper subpaths re-export this implementation.
Framework-specific bootstrap/registry code remains in that compatibility package.

`resource-formats` records native API routes separately from ResourceLoader and
executable producer support. TSCN/TRES load natively with their dependencies.
The default browser and Node registries provide these Godot 4.6.1 producers:

| Recipe | Native output | Encoding |
| --- | --- | --- |
| `godotjs/png-ctex` | `CompressedTexture2D`, `.ctex` | CTEX v1 containing the original compressed PNG |
| `godotjs/jpeg-ctex` | `CompressedTexture2D`, `.ctex` | jpeg-js 0.4.4 RGBA decoding, then PNG with fixed fflate 0.8.2 deflate settings |
| `godotjs/wav-pcm` | `AudioStreamWAV`, `.res` | RSRC v6 containing PCM8/16 mono/stereo data at the source sample rate |

Schema 4 selects recipes explicitly through `resourceImports`, for example
`[{resource: "res://audio/tone.wav", converter: "godotjs/wav-pcm"}]`.
`prepareBuildPlan` requires an executable `resourceConverters` registry and an
actual `resourceTarget`. New binary recipes require
`resourceAbi: 'godot-4.6.1-resources-v2'`; each receipt also identifies its output
extension, native resource type and format ABI. Generated resources and `.import`
remaps enter the artifact overlay. Source bytes, `.uid` sidecars and original
exports remain intact. Request, sidecar and existing import UIDs must agree.
Both compiler variants expose the captured `sourceHash` and completed
`importReceipts` as outer build metadata. ArtifactSet identity remains the
package closure's identity; it does not acquire a synthetic single-PCK hash.

PNG validation checks CRCs, chunk order, deflate size and row filters before
producing a resource. This route accepts noninterlaced 8-bit still PNG.
JPEG SOF dimensions are checked before decoding, and the pinned software codec
limits its allocations to 128 MiB and its frame size to 16 MP. The same codec and
fixed PNG compression settings run in Node and browser Workers, with no canvas,
OS JPEG decoder or host compression library in the default JPEG identity.
`resourceLimits` bounds decoded pixels/bytes and total generated bytes;
`packBuildPlan` also enforces the PCK limit. A flat white 2048² test image produces
approximately 21 KiB of CTEX for either route. Other images have different
compression ratios, and decoded JPEG pixels are stored losslessly in the CTEX.
Only `mipmaps=false` is supported; unsupported editor presets fail explicitly.

Texture type migration is explicit: `godotjs/image-rgba` retains the legacy
`ImageTexture` Base64 TRES route and uses the supplied decoder. The Playground
provides its identified canvas decoder for that recipe. Existing recipes are
preserved when assets are imported. The legacy `pcmWavConverter` export and an
explicit `godot-4-text-resource-v1` target retain WAV producer `1.1.0-base64`;
`godotjs/wav-pcm-base64` is also available explicitly. Binary WAV uses
`2.0.0-rsrc6`. JPEG's compressed PNG writer has producer version `2.0.0` with
codec/settings identities; `jpegCtexConverter(decoder, {compression:'stored'})`
retains the explicit `1.0.0-png-store` writer. Older output bytes identified by a
receipt remain preserved, with `W_RESOURCE_PREVIOUS_OUTPUT_RETAINED`, and still
count toward the artifact budget.

Receipts imported in project JSON cannot establish that a producer executed.
Only module-owned deterministic producers can use the opaque execution cache;
custom producers reuse verified execution within their registry session.
Completed records bind the current recipe and implementation, verify every
output hash, and publish atomically through host-owned storage. Corrupt records
are discarded and rebuilt. Node's default cache is outside project directories;
the Playground uses a separate bounded IndexedDB cache. Cache hit/miss telemetry
does not alter receipts, reasons or artifact identity. An injected decoder's
identity and function are captured at registration; its owner remains responsible
for versioning any internal mutable state.

SVG, GLTF/GLB and OGG have recorded native API routes, with no generic
ResourceLoader producer in this registry. Blender, FBX and other editor producers
remain separate format-specific work. The binary resource probe checks real
browser Worker production, Node/browser byte parity, reopened persistent caches
and native PCK loading. Product Web/GPU rendering and editor import/export are
separate acceptance tests.

## Shared compiler and Node adapter

`compiler-policy` defines `godotjs-engine-compiler/1`. The same policy derives the
checking and native CommonJS emit options; checking deliberately uses `noEmit`
and retains source extensions. `createProjectTypeEnvironment` provides an owned
virtual declaration/module view for both compiler checks and editor language
services. It never reads host `node_modules`, Node ambient types or system libs.

`createCompilerEnvironment` captures declarations, module routes, runtime modules
and vendor bytes before hashing them. Its identity includes their actual content,
the TypeScript/policy version and the adapter-validated target. `compileBuildPlan`
owns preparation, overlay verification, PCK and artifact receipt generation.
`compileProject` checks that same plan's source snapshot before building. Existing
`BuildPlan.compatibility` remains intact: old Node classes keep their constructor
bootstrap, and old component documents use an explicitly supplied current React
startup adapter. The neutral compiler imports no React or application code.

`ProjectWorkspace` pins immutable revisions and releases each job independently.
After an initial `capture`, `captureChanges(changed, removed)` shares unchanged
private `SourceFile` records without reading or hashing their binary payloads.
`ProjectLanguageService` preserves the TypeScript service while file versions,
resolution routes and the declaration environment invalidate affected work.
`ProjectBuildCache` bounds text, emit and PCK records; its private verified package
descriptors avoid repeated SHA/MD5 work on unchanged resource packages. Cache
hits and misses are execution telemetry and do not alter artifact identity.
Cancellation and superseded output jobs cannot publish their older result.

Compilation returns a discriminated product: `variant: 'single-pack'` supplies
`pack` and its receipt; `variant: 'pack-set'` supplies `artifactSet` and no redundant
full PCK. A set requires the matching target's `artifactSetAbi: 1`. Resource PCK
identities depend on their own members and packing format, and the bootstrap owns
the union index and global UID/import metadata. The set identity remains outside
the packages, avoiding identity cycles. Runtime admission validates actual PCK
directories and checksums before mounting any resource pack.

Both variants return `sourceHash` and `importReceipts`. The shared
`compileResultMetadata` adapter exposes these with `buildKey`, `artifactId` and
`outputOverlay` in the browser response and Node audit manifest. A set uses
`artifactSetId` and keeps its package manifest unchanged; it has no single-pack
SHA or receipt. Node set exports write the independent build evidence to
`application.pck.manifest.json` beside `artifact-set.json`. The editor saves
validated import receipts as project metadata while preserving source files and
the retained original document. Matching stored hashes alone do not certify a
trusted converter execution.

The Node entry and `godotjs` CLI require Node.js 22.14.0 or later, including
`node:module.findPackageJSON()` for import-only startup adapter resolution.
Repository builds and CI use Node.js 24 or later.

The separate `@godot-js/project-tools/node` entry reads local files and a matching
`engine-release.json`, validates descriptor and asset bytes, then calls the shared
compiler. The `godotjs` command supports:

```sh
godotjs check --project project.json --release /path/to/engine-release.json
godotjs build --project /path/to/native-project --release /path/to/engine-release.json --output work/game.pck
godotjs export-pck --project /path/to/native-project --entry src/start.ts --release /path/to/engine-release.json --output work/script.pck
godotjs build --project /path/to/native-project --release /path/to/engine-release.json --artifact-set work/game-set
```

A project input can be a Schema 1–4 JSON document or a directory. Directory inputs
use the configured main scene unless `--entry` (ordinary `start(ctx)`) or
`--main-scene` is supplied. Source resources, import sidecars and imported caches
are retained; editor state, generated GodotJS outputs, `.git`, `node_modules`,
toolchain assets and the selected output are excluded. Symlink inputs fail
explicitly. Build/export writes the PCK and its adjacent `.receipt.json` and
`.manifest.json`, including the matched target IDs and final pack hash. Browser
transport still supplies its own pinned site/release context when launching it.
`--artifact-set DIR` instead writes `application.pck`, content-addressed
`packs/<sha256>.pck` files and `artifact-set.json`; it is mutually exclusive with
`--output`. The native startup hook mounts the complete set before UID loading.
Node writes candidates first and admits the current job before publishing the
root pack. The default trusted producer cache lives outside project directories;
`--resource-cache DIR` selects a host-controlled cache location.

Old React component documents need the optional matching React build adapter;
it can be resolved from the project or passed as `--startup-adapter MODULE`.
Native projects do not load the React vendor. The Node entry supplies the default
PNG CTEX, shared deterministic JPEG CTEX and binary PCM WAV producers. The
explicit legacy ImageTexture recipe requires its identified decoder through the
shared API. Same-target parity requires matching declaration/runtime bytes,
resolution, startup adapter, resource producer and PCK options.

The Playground uses the same type environment and artifact facade. Its editor
completion/hover protocol remains application-owned. The main thread sends one
owned full source revision followed by changed/deleted file deltas; repeated
queries carry no unchanged binary data. The Worker checks document/revision and
transport order, then captures that revision before any asynchronous build work.
Demo resource pack members join the same source snapshot and UID aggregate before
startup, and are never mounted late from application code.
