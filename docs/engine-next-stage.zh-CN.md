# 引擎下一阶段改造建议

状态：待评审建议。原分析日期：2026 年 11 月 17 日（`a518dab`）。实施进展更新至 2026 年 11 月 27 日（`595d135`）。

已确认的产品定位与引擎平台边界见[引擎核心目标与平台边界](engine-goals.zh-CN.md)。本阶段建议交付一条可由独立平台调用的项目修改、构建、浏览器运行、观察与交互验证链路。

Playground 接入 AI 助手的前置方案已完成选定范围的验收。环境、检查构建、产物衔接和运行事实已落地。Playground 随后验收了基于 Summer 4.9.2 的物理帧输入、同帧采样和生命周期回放。 [引擎最小合同与核心回归 V4](design/engine-minimum-contracts-v4.zh-CN.md) · [交付与接入记录](engine-minimum-contracts-delivery.zh-CN.md) · [Playground 回放验收](../apps/playground/README.md#lifecycle-events)

Playground 已接入 `engine.get_diagnostics({})`，按编辑版本读取现有检查、构建和关联运行的退出诊断。真实 2D/debug Worker 已验收类型错误定位、失败构建与旧运行隔离、修复后启动和启动异常诊断。Full/debug Worker Direct 串联验收从修复版继续试玩，离线检查确认同帧画面位置为 `64 → 128 → 64`，两次试玩运行均正常退出并完成宿主清理。 [诊断与修复演示](../apps/playground/README.md#diagnostics-and-repair) · [本地诊断合同](design/playground-agent-api-p0.zh-CN.md)

## 优先结论

**让独立接入方完成一次真实游戏迭代。** 抽取必要的公共装配能力，在 Playground 之外验证现有画面、有限输入和结构化结果，再补齐接入中暴露的缺口。

共享编译、增量缓存、资源生产器、Worker runner 和退出事实已经存在。下一阶段应复用这些实现，将投入集中在平台接入的实际断点与 AI 自主验证所缺的运行能力。

## 独立分析的侧重点

| 视角 | 第一优先项 | 对阶段范围的影响 |
| --- | --- | --- |
| 通用平台接入 | 独立消费公共编译与预览链路 | 以第二个接入方暴露真实缺口；补基础版本校验与结果关联 |
| 运行反馈 | 在独立接入链路验证画面观察与有界输入 | 用真实试玩验证采样、输入回执和退出 |
| 构建素材与交付 | 可搬迁的编译预览资产与独立消费验证 | 复用发布身份和校验；素材扩展先提高能力可发现性 |
| 架构与投入产出 | 独立消费者验证最小闭环 | 先以真实调用决定抽取范围；已能独立使用的部分保持现状 |

公共接入为运行反馈提供通用交付入口，运行反馈为平台提供自动验证与修复所需的新事实。两项可以在共同身份和结果合同确定后并行实施。

## 首先改造公共接入与项目变更

交付一条无需导入应用内部代码的调用链：匹配的发布资产与宿主读取器，准备编译环境，校验并构建项目，将产物交给默认 Worker 预览，获得诊断与退出结果，再提交下一次变更。

最小改造范围：

- 从工作台抽取发布清单、声明、命名配置和所需运行模块的通用装配，复用 `CompilerEnvironment`、目标和身份验证。
- 从预览适配抽取编译产物到公共运行输入的必要转换，保留实际包、收据、目标及宿主资产闭包校验。
- 由平台显式提供资产位置、读取或授权适配、存储和预览容器；示例选择、Monaco、IndexedDB、全局页面 URL 与产品重试策略留在应用。
- 复用现有快照与 delta，提供带基础快照身份的文件替换、删除批次。先支持完整文件变更，失败批次无部分生效；过期基础版本返回冲突。
- 将检查、构建、运行及后续观察的结果关联到实际源版本、操作、构建、产物和运行身份；重试、取消与过期结果有明确处理。

引擎的内存版本与输入快照不能代替平台数据库事务。平台继续负责持久化提交、协作合并和历史回退。同步工作不能被 `AbortSignal` 立即抢占时，应撤销结果发布与后续执行，并准确报告取消状态。

优先在现有 `engine`、`project-tools` 和发布工具职责内完成抽取。隔离消费使用实际打包产物并解析其依赖，避免依赖 checkout 或 workspace 源码路径。

成本量级为中，主要是 TypeScript 装配、发布工具和接入验证。SDK 接入本身不以新增原生 ABI 为前提；抽取改变源码路径、SDK 输出或宿主字节时，继续更新对应证明、身份和候选验收。

## 在独立接入链路验证运行观察与交互

独立接入先复用已验收的 Dedicated Worker Direct 画面采样与输入，再按实际缺口补齐键鼠操作、诊断和等待。平台负责决定操作步骤、理解画面和判断游戏是否符合用户意图。

| 能力 | 最小交付范围 |
| --- | --- |
| 画面观察 | 返回可解码的图像、尺寸、几何版本、采样序号与完整运行关联 |
| 输入 | 按键按下与释放、指针移动与按下释放，坐标绑定视口和几何版本，限制数量和持有时长 |
| 等待 | 等待明确的分发阶段、后续原生进度、渲染提交或指定事件，标明来源与超时 |
| 诊断与结果 | 保留源码位置、错误类别、运行身份及已观察到的阶段，结算成功、失败、取消、超时与未确认 |

保留既有项目命令和 transport receipt 的含义。新操作区分本地准入、进入输入桥、实际原生消费和后续渲染采样；只有存在对应执行端观察时才能声明该阶段已完成。后续画面提交也不能独立证明游戏规则正确。

独立接入先使用已通过 Playground 真实采样验收的 Dedicated Worker Direct。扩展到 Bitmap 时，以实际支持的能力单独验收。采样发生在资源所属 realm 和正确时点，输出拥有独立字节或明确释放责任，不能窃取呈现中的 ImageBitmap 或 frame ticket。尚未支持的模式显式报告能力限制。

停止或替换运行时，撤销新请求准入，取消排队操作，释放自动化持有的键和指针，并结算所有等待者。已经发出的输入不能因取消而回滚；执行端已销毁或结果丢失时保留未确认阶段。迟到响应只属于原运行。

合成游戏输入遵循实际浏览器权限和用户激活条件。游戏渲染图像、页面显示、音频输出与物理屏幕是不同观察范围。

成本量级为中到大，涉及控制协议、输入与渲染时序、资源清理和真实浏览器验收；必要时需要匹配原生 hook 与引擎资产重建。

## 随接入暴露已有资源能力

先将已有目标、生产器和导入路径变成可查询、可预检的结果，供平台在生成和修改前选择素材方案。结果包括直接 API 或 ResourceLoader 路径、格式与选项、依赖、目标类型、预算和可行动失败。

复用已有 PNG、JPEG、WAV 转换、收据和缓存；原生 API 可读取某种数据，不等于浏览器已经提供该格式的通用 ResourceLoader 生产器。显式导入请求缺少生产器时给出失败，保留使用原始数据的合法直接 API 路径。

用真实接入项目选择下一种需要增加的格式。首批验证 fixture 的选择用于覆盖合同，不预先限定平台的游戏品类。

## 阶段完成标准

阶段完成应同时满足接入通用性、运行反馈和故障恢复：

1. Playground 改为消费抽取后的公共能力，继续使用自己的存储、资源来源与产品界面。
2. 另一个最小程序化客户端从打包 SDK 独立安装，使用自己的内存或其它存储、不同资源来源与独立预览配置；它不导入 `apps/playground`、其它包的 `src`，也不复制内部组装逻辑。
3. 两个接入方共用匹配 release 与公共合同，完成项目变更、检查、构建、真实浏览器运行、观察、输入、停止和再次修改运行。Node 构建产物送入独立预览作为额外交叉验证。
4. 普通场景入口、显式 `start(ctx)` 与按需 React 入口有相应覆盖；普通项目无需加载 React vendor。相同语义构建输入使用相同目标和选项时，身份及产物字节符合现有一致性合同。
5. 一个自包含游戏 fixture 可通过公共接口取得前后画面并接受真实输入；验收通过受控原生状态或独立观察验证效果，保留项目自报事件的来源。
6. 覆盖一次成功修改、类型错误与修复、运行异常与修复、素材替换及停止重启。代码、资源和配方由程序化操作提交，常规验证没有人工补写步骤。
7. 覆盖错误基础版本、错引擎或 hash、资源缺失、取消、旧构建与旧画面迟到、输入中途停止和 Worker 失联；所有结果关联实际版本，资源与退出状态准确结算。
8. 项目可由一个接入方导出，交给另一方构建与运行，保留入口和资源含义。

浏览器编译和 Node 构建只是两种宿主。上述结果应称为两个独立参考接入通过；真实商业平台接入与真实 AI 创作完成率由后续平台验证。固定变更序列验证引擎可调用性，模型选择、规划和修复质量留在平台。

首条工程闭环可以先在一个明确记录版本的真实浏览器中成立，随后继续执行变更影响到的现有浏览器和交付门禁。单浏览器通过不改变原有跨浏览器、设备、权限与发布要求。

## 后续改造的选择

更多资源格式按实际作品阻塞推进；公共 npm 发布在隔离安装和组合消费验证之后安排。通用场景 inspector、精确帧步进、确定性回放与更广设备支持按需要另行设计。

模型服务、Agent、MCP 服务端、会话 UI、素材生成和云端项目协作由平台或独立适配实现。新一轮原生核心重构、执行后端切换和大型统一 facade，需要具体接入或运行缺陷作为依据。

如果独立消费者已经能通过现有公共接口完成某部分链路，对应抽取缩到最小，将实施投入转向观察、交互和故障恢复。阶段价值由真实项目能否完成迭代衡量。
