# 引擎核心目标与平台边界

对齐日期：2026 年 11 月 17 日。

## 核心定位

为 AI 游戏创作平台提供通用的游戏项目、构建、运行和验证底座，让创作者仅通过 AI 会话完成游戏创作与持续修改，无需手工编码，并能在浏览器内预览和试玩游戏产物。

引擎侧提供可由程序完整调用的能力；平台侧将用户意图转化为这些能力的调用。不同平台可以选择不同的模型、Agent、会话产品、存储与部署方案，复用同一套引擎合同和实现。

长期目标之一是对齐 [Summer Engine](https://summerengine.com/) 面向 Agent 的 API，逐步覆盖能力发现、项目操作、检查与构建、预览运行、诊断和验证。通过真实接入用例检验这些调用能否完成核心工作流，以及接入方能否依据返回结果确认实际执行情况。

代码、场景、资源和配置是 AI 持续维护的项目产物。创作者通过描述需求、试玩和反馈控制变化；常规创作流程不能依赖用户补写代码、手动修补项目或打开原生编辑器才能继续。对于尚未支持的操作，引擎返回明确的能力限制，由平台调整方案或报告阻塞。

## 服务对象与创作流程

直接接入方是 AI 游戏创作平台，最终用户是希望通过对话创作游戏的人。AI 是项目的主要操作者；引擎公共接口同时适用于自动化程序和测试工具。

完整创作流程为：

```text
用户描述与反馈
  → 平台规划并生成项目变更
  → 引擎校验项目并构建产物
  → 浏览器运行与试玩
  → 引擎提供运行观察和测试结果
  → 平台分析结果并生成下一次变更
```

浏览器内会话与预览是必要产品体验。模型推理、素材生成及重型处理的部署位置由平台决定；引擎通过明确的宿主适配接入这些流程。

## 引擎与平台的职责

| 能力 | 引擎侧 | 平台侧 |
| --- | --- | --- |
| 游戏运行 | 场景、渲染、物理、音频、输入、脚本和生命周期 | 游戏意图、玩法规则、风格与内容规划 |
| 项目模型 | 项目格式、入口、代码与资源依赖、源快照和项目约束 | 用户项目管理、持久存储、协作与历史版本 |
| 项目修改 | 接收带基础版本的变更，校验并形成一致的构建输入 | AI 生成代码与补丁、安排修改顺序、处理协作冲突策略 |
| 检查与构建 | 类型检查、编译、资源处理、缓存、打包和目标匹配 | 触发时机、任务调度、算力分配和费用控制 |
| 素材处理 | 支持格式与选项声明、资源转换、依赖和引用校验、加载 | 图片、模型、动画、音乐的生成或检索，以及版权管理 |
| 浏览器预览 | 加载产物、运行会话、输入与呈现、音频、停止重启和资源回收 | 预览界面、会话联动、访问授权和预览站点部署 |
| 观察与测试 | 结构化诊断、源码定位、受支持的状态与画面观察、交互驱动和测试执行 | 制定符合用户意图的测试、分析结果、评价玩法与体验 |
| 自动修复 | 提供失败事实、修改执行与重新验证能力 | 推理修复方案、选择工具、控制重试和判断何时结束 |
| 版本与交付 | 引擎和能力版本、构建与产物身份、兼容性校验和产物生成 | 创作检查点、发布审批、托管、分享和渠道运营 |
| 执行约束 | 执行端能力校验、资源额度、取消与清理机制及结果 | 租户权限、部署隔离、网络与素材访问策略、产品使用配额 |

引擎对执行事实和机制负责，平台对创作决策和产品流程负责。平台可以决定是否重试；引擎必须说明当前操作的状态、取消是否生效、旧运行是否结束以及资源清理是否得到确认。

项目持久历史与构建快照有不同职责。平台保存对话、项目版本与用户操作；引擎捕获某次检查、构建或运行实际使用的不可变输入，并拒绝将过期结果关联到新的项目版本。

引擎可执行平台提供的通用测试步骤，并返回观察结果。游戏是否符合用户描述、是否有趣，以及下一步如何修改，由平台依据这些结果判断。项目自行上报的业务事件与引擎、宿主实际观察到的运行事实应保留不同来源。

## 通用接入合同

公共能力按以下职责组织；具体 API 命名和实现次序由后续设计确定。

| 合同 | 接入方需要的能力 |
| --- | --- |
| 能力发现 | 获取版本、目标、项目与资源支持范围，以及可用的运行和测试能力 |
| 项目操作 | 读取项目、提交带基础版本的变更、校验并获得一致的源快照 |
| 检查与构建 | 发起检查或构建、订阅进度、取消任务、取得诊断和产物 |
| 运行会话 | 创建预览、启动、停止、重启和订阅运行事件 |
| 观察与验证 | 查询受支持的状态、观察画面、发送交互输入、执行测试并获得结果 |
| 产物消费 | 获取产物清单、资源依赖、版本要求和校验信息 |

合同需要关联项目版本、操作、构建、产物和运行身份。诊断、截图、输入回执与测试结果必须能定位到实际使用的输入和运行；日志到达顺序不能代替这种关联。

长期操作需要明确的进度、取消和终态语义。命令接纳、同步分发、异步完成和实际生效分别表达；超时、强停或缺少观察时保留失败或未确认事实。

## 通用设计原则

1. **模型与工具传输可替换。** 核心接口接收项目、变更和执行请求。模型工具调用、MCP、HTTP 等由适配层映射到同一套能力，核心实现不依赖某个模型供应商或 Agent 框架。
2. **平台业务留在平台。** 会话、账号、租户、计费与运营信息通过平台上下文关联，不能成为游戏项目或引擎算法的必要输入。
3. **宿主服务有明确边界。** 文件和资源读取、存储及执行环境通过接口接入。浏览器与 Node 适配器复用项目和编译核心；浏览器适配负责实际需要的 DOM、Canvas、音频与输入服务。
4. **创作方式可以组合。** 原生场景、普通 TS/JS 和可选 React 使用同一引擎能力、项目体系和生命周期。平台可选择适合其 AI 的生成方式。
5. **结果可以由机器消费。** 能力、错误、位置、进度、状态和退出结果具有版本化结构。稳定接口避免要求平台解析工作台界面或自由文本日志。
6. **项目与产物可迁移。** 导出内容包含代码、资源依赖和引擎要求；脱离原平台会话后仍可由匹配工具构建和运行。
7. **扩展有显式合同。** 新资源处理器、编程层与宿主能力声明输入、输出、版本及目标范围，继续参与统一构建身份、运行约束与验证。
8. **以核心能力和结果语义为对齐重点。** 具体接口兼容由实际接入需求决定。有明确复用目标时，在适配层映射方法名、参数和传输，并用真实用例验证兼容范围。 [Summer Engine 操作参考](https://docs.summerengine.com/mcp/operations/engine)

## 仓库职责映射

| 位置 | 当前职责与演进归属 |
| --- | --- |
| `bridge/`、`impl/`、`weaver/` | 原生引擎、脚本绑定、对象身份与生命周期 |
| `packages/engine/` | API 描述、运行合同、身份、退出事实及浏览器运行适配 |
| `packages/project-tools/` | 源快照、项目与启动模型、共享编译、资源处理和产物生成 |
| `scripts/jsb.react/`、`scripts/jsb.react-build/` | 可选 React 编程层与相关构建适配 |
| `apps/playground/` | 参考平台、工作台、存储和集成验证 |
| `tests/`、包内测试与 CI | 各层合同、真实运行和交付验证 |

新通用能力应复用已经存在的中立实现，按实际职责和接入需求抽取。Playground 的界面、数据库布局、示例选择和产品策略不能成为其它平台接入引擎的前提。

当前共享编译、Worker 预览、诊断、资源打包与生命周期已有实现。完整的公共项目操作、画面与状态观察、交互测试和独立平台接入合同仍需继续设计和验证；本定位中的目标能力不等同于当前支持矩阵。

## 成功标准

最终创作者能够在零手工编码的情况下，通过连续对话完成一款可玩的游戏，并继续修改、验证和交付它。该结果由平台与引擎共同实现。

引擎侧以以下结果验证自身是否支撑了目标：

- 平台可以通过公共接口完成项目变更、检查、构建、预览、观察和验证，常规链路没有必须手工操作的步骤。
- 至少两个独立接入方复用相同项目与产物合同；新增接入只需宿主适配和产品流程，不修改编译器或运行时核心。
- 同一项目的失败、取消、停止重启和版本切换能产生可关联的结果，过期消息和产物不会覆盖新版本。
- 项目可以导出并在原平台之外用匹配引擎运行；资源缺失、目标不支持及清理未确认均有明确结果。

平台可以进一步统计首次可玩产物耗时、零手工编码完成率、连续修改成功率与自动修复成功率；引擎提供相应执行与验证事实。具体品类优先级、性能预算、发布范围和阶段计划另行评审。
